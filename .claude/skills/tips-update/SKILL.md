# /tips-update

Web検索で最新のAI活用事例を収集し、Tipsを追加するスキル。

## トリガー

- `/tips-update`
- `Tips更新して`
- `新しいTipsを追加して`

## 処理フロー

1. **現状確認**
   - obsidian-sns-dataをclone（`/tmp/data`）
   - 各カテゴリのTips残数を確認（`grep -r "used_count: 0"`）
   - 残り少ないカテゴリを優先

2. **情報収集**
   - trend-researcherエージェント×3を並列起動
   - 検索クエリ例:
     - エンジニア: `エンジニア AI活用 事例 2026 生産性`
     - コンサル: `コンサルティング AI活用 事例 2026 戦略`
     - バックオフィス: `バックオフィス AI活用 事例 2026 効率化`

3. **Tips作成**
   - 収集した事例をMarkdownファイルに整形
   - 既存タイトルとの重複チェック
   - デビルズアドボケート評価で品質確認

4. **確認・追加**
   - 作成したTipsをユーザーに確認
   - 承認されたらobsidian-sns-data/ai-tips/に追加
   - コミット・プッシュ（`git pull --rebase` してからpush）

## Tipsファイル形式

```markdown
---
id: "eng-XXX"
category: "engineer"
title: "【事例】〇〇社：△△で□□を実現"
tags: ["タグ1", "タグ2", "タグ3"]
created_at: "YYYY-MM-DD"
used_count: 0
---

📊 実績: 具体的な数字・成果（出典名 YYYY）

説明文（2-3文）

💡 実務で効くポイント:
- ポイント1
- ポイント2
- ポイント3
- ポイント4

🎯 行動を促すメッセージ

🔗 参考: URL
```

## Tips作成のポイント

### タイトル
- `【事例】` または `【実践】` で始める
- 具体的な数字・成果を含める
- 例: `【事例】LINEヤフー：Copilotで1日2時間の工数削減`

### カテゴリ別のトーン
- **engineer**: 技術的な具体性、ツール名を明記
- **consultant**: ビジネスインパクト、ROIを強調
- **backoffice**: 日常業務との関連、専門用語を避ける

## デビルズアドボケート品質チェック

Tips作成後、以下3視点で評価し、不足があれば修正する:

| 視点 | チェック内容 |
|------|-------------|
| 懐疑派 | 「本当にそんなに効果あるの？」→ 出典・数字の裏付けがあるか |
| 現実派 | 「実際の現場で使えるの？」→ 今日から試せるアクションがあるか |
| リスク派 | 「何が起きうるの？」→ 制約・注意点に触れているか |

**NGパターン**（これに該当したら修正）:
- プロンプト例だけで終わっている
- 出典URLがない
- 具体的な数字・企業名がない
- 「AIに聞いてみよう」のような抽象的なアクション
